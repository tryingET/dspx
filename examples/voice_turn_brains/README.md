# Voice-turn brain candidates

This example set contains six **separate** DSPy programs for the batch hardware voice-turn. It is deliberately not an answering-mode router: the caller selects one manifest before invoking `dspx program-run`.

| Mode | Response contract | Topology |
|---|---|---|
| `simple` | Direct, concise answer | persona → `Predict` |
| `elaborate` | Developed answer with context and caveats | persona → `ChainOfThought` |
| `researched` | Bounded-corpus answer with exact document-ID citations | persona + `Retriever:inline_corpus` → answer |
| `deep-research` | Multi-perspective bounded-corpus synthesis with citations | persona + `Retriever:inline_corpus` → synthesis |
| `socratic` | One or two focused guiding questions | persona → `ChainOfThought` |
| `bloom` | Correct, teach, then end with an unanswered transfer question | persona → `Predict` |

## Layout and selection

- `intents/<mode>.yaml` — source intent for each program.
- `intents/corpus/voice_turn_corpus.jsonl` — declared local corpus used only by the two research modes.
- `candidates/<mode>/original/manifest.json` — program-gen candidate.
- `candidates/<mode>/optimized/manifest.json` — materialized GEPA candidate.
- `refinement/<mode>/` — GEPA result, optimizer output, and materialization result.
- `manifest-index.json` — portable relative-path index for all original and optimized manifests.
- `ai-control-brains.json` — exact six-mode optimized-manifest binding consumed by the LACP `DspxBrain` adapter.

A runtime adapter should receive this example directory through configuration and prefer the indexed optimized manifest. Falling back to the original manifest is allowed only when the optimized path is absent and the caller's contract explicitly permits that fallback. Do not hardcode this repository's workstation path in another package.

Example direct invocation from the DSPx repository root:

```bash
export DSPX_PROVIDER=openai-compatible
export DSPX_OPENAI_COMPAT_API_BASE=http://127.0.0.1:1234/v1
export DSPX_OPENAI_COMPAT_MODEL=baseline-text
export DSPX_TRUSTED_PROGRAM_ROOTS="$PWD"

inputs=$(mktemp "${TMPDIR}/voice-turn-inputs.XXXXXX.json")
outdir=$(mktemp -d "${TMPDIR}/voice-turn-run.XXXXXX")
printf '%s\n' '{"transcription":"Why do seasons change?","persona_intent":"A patient science teacher."}' > "$inputs"
just dspx program-run \
  --manifest examples/voice_turn_brains/candidates/simple/optimized/manifest.json \
  --inputs "$inputs" \
  --outdir "$outdir" \
  --skip-oracle-index \
  --json
```

Honor `TMPDIR` and use a fresh output directory for every run.

The LACP CLI accepts the repository and binding as explicit configuration rather than embedding a workstation path:

```bash
ai-control voice-turn \
  --transcript-from-clipboard \
  --brain dspx \
  --answering-mode socratic \
  --dspx-repo "$PWD" \
  --dspx-config examples/voice_turn_brains/ai-control-brains.json \
  --persona-intent "A patient Socratic teacher." \
  --play
```

## Grounding boundary

`researched` and `deep-research` materialize the declared local snapshot as `Retriever:inline_corpus`. They do not bind external retrieval or ReAct tools. A cited identifier must exactly match a retrieved document ID in `voice_turn_corpus.jsonl`; an ID with an appended score is not valid. Unsupported questions must degrade to the intent's exact no-sources response. Because an LM can still violate this instruction, a consuming runtime must compare response citations with the exact IDs in the runtime retriever trace and fail closed on invented or decorated IDs.

## GEPA boundary

Each original candidate was given behavior examples, optimized with a bounded `--max-metric-calls 2` run, and materialized as a separate optimized candidate. DSPx now defaults GEPA execution to one thread to avoid concurrent pressure on a local provider. The refinement and candidate artifacts are empirical evidence only: they do not select a winner, approve promotion, activate production, mutate governance, or transfer authority.

The optimized program directories include trusted-local Python pickle payloads generated by DSPy. Load only repository-controlled candidates, keep `DSPX_TRUSTED_PROGRAM_ROOTS` bounded to a trusted checkout, and never accept an operator-supplied pickle path as an untrusted runtime input.

Generated manifests and behavior evidence retain generation-time provenance, including local execution paths. Those paths are evidence, not configuration and not a cross-repository runtime contract. A consuming receipt must not copy raw artifact paths or conversational text from these artifacts.

## Verification posture

At materialization time, every original and optimized candidate passed replay checking and a dedicated live `program-run`; runtime trace coverage was complete. The dedicated research proof responses cited only exact declared corpus IDs, and Bloom ended with an unanswered re-quiz. Generation-time behavior evidence can still contain nonconforming LM drafts, including decorated or invented citation IDs, so it is evidence rather than a passing citation gate. These artifacts do not prove current provider health or a current end-to-end voice turn.
